# wesleyegbertsen.github.io

Personal site at <https://www.wesleyegbertsen.nl/>, built with Vite, React and TypeScript.

## Develop

```
npm ci
npm run dev        # dev server
npm test           # unit and component tests
npm run typecheck
npm run lint
npm run build      # production build into dist/
npm run e2e        # real-browser tests with Playwright (see .claude/skills/site-e2e)
```

Node 24 or newer (see `.nvmrc`).

`package.json` has an npm `overrides` entry that lets `eslint-plugin-jsx-a11y` run on ESLint 10: the plugin works there (checked with deliberate violations) but its declared peer range still stops at ESLint 9 (upstream: jsx-eslint/eslint-plugin-jsx-a11y#1075). Remove the override once a release declares support.

TypeScript runs side by side, as Microsoft recommends for 7.0: `tsc` (typecheck and build) is TypeScript 7 (`@typescript/native`), while the package named `typescript` is the 6.0 compatibility package (`@typescript/typescript6`), because TypeScript 7 has no programmatic API and `typescript-eslint` needs one (tracked in typescript-eslint#10940; a new API is expected in TypeScript 7.1). When `typescript-eslint` supports TypeScript 7, point `typescript` back at the real package and drop `@typescript/native`.

## Layout

An architecture overview drawn from the code, with source citations, is in [docs/architecture/overview.html](docs/architecture/overview.html) (open it in a browser).

- `src/features/*`: the hobby easter eggs (matrix backdrop, Poké Balls, cat, Game Boy), each with its hooks and tests
- `src/pages/*`: the two routed pages, `HomePage` (`#/`) and `ProjectsPage` (`#/projects`); `src/App.tsx` holds what every page shares (backdrop, site menu, Game Boy, social bar)
- `src/components/*`: the social bar and its panels, the left site menu (`SiteMenu`) and the project card
- `src/data/*`: skills, work experience, education, menu items and projects as typed data, edit these to update the site: add a line to `navigation.ts` for a menu item, add an entry to `projects.ts` (with screenshots in `src/assets/images/projects/`) for a project
- `src/features/theme/*`: the matrix background colour is the site theme. `themes.ts` holds one palette per colour (green, red, blue, white) and is the only place to change a colour; a test checks every pairing for contrast. The chosen theme is set on `<html>` as `data-theme` plus the CSS custom properties `--accent`, `--accent-hover`, `--accent-on-light`, `--accent-soft` and `--on-accent`, which the CSS modules use instead of hard-coded colours (GitHub and LinkedIn keep their brand colours)
- `src/features/terminal/*`: the shell on `#/terminal`. Its `play` command opens Career Quest, a Game Boy-style adventure in `game/`: `engine/` is the pure game logic, `content/` is what to edit (maps as text grids in `maps.ts`: the town, the routes east and west, Hobby Hills and the two floors of the cave; people, signposts, gold stars, errands and the ten hobby stops (`HOBBIES`, a draft to rewrite) in `story.ts`; enemies per area (`AREAS`), levels and XP (`LEVELS`), the moves offered at level 5 and 10 (`LEARN`), items, the money (`ECONOMY`), the coins that are handed out (`REWARDS`) and what the shop sells (`SHOPS`) in `battles.ts`; the tunes and sound effects as note text in `music.ts` (a way between maps says which effect it is: `door`, `path` or `cave`); the facts come from `src/data`), `render.ts` draws it on a 160x144 canvas, `audio/` plays the music and the effects (synthesized with the Web Audio API like a Game Boy: two pulse voices, a triangle and noise; no audio files). `M` or the Sound button switches the sound off; the Start menu has a Settings tab with the sound switch, the volume (left and right, 0 to 100%, 50% at the start; 100% is master gain 0.25), the LCD look of the screen (a CSS grid laid over the canvas, on by default) and the mode, GB or GBC: Game Boy Color mode draws every tile and sprite from a copy of its sheet recoloured into one of the four-colour palettes of `palettes.ts` (a rule per name gives each its palette; the copies are made in the page the first time colour is asked for), and the console around the screen swaps its CSS custom properties on `data-mode="gbc"` for a translucent purple body with "CAREER QUEST COLOR" on it (B on the title screen switches the mode too); and LIGHT, BRIGHT or DIM: DIM draws the picture as a Game Boy Color screen without a frontlight looks, darker and less colourful, in GBC and in GB (`dim` in `palettes.ts`: each channel goes a quarter of the way to the colour's own luma, then the whole is darkened to 82%; the sheets are recoloured once, the LCD look is left alone; off at the start, `DIM_START` in `settingsStore.ts`); all five are kept in memory for the session (`settingsStore.ts`). Wins give XP (levels 1 to 10) and COINS: the enemy's level times 2 for a wild one, times 10 for a boss. Coins are handed out too (`REWARDS`): for the two errands in town, for a full stamp card in Hobby Hills, in four chests off the main path (by the flag of the chest) and by Wesley after the third battle of the last fight; a test keeps the amounts modest (a chest under what the first boss drops, all gifts together under what the four badge bosses drop). The pay at the very end cannot be spent, the game ends there: the ending shows the purse as a score. The Start menu has the level and the XP on one row, the energy and the coins on the next, then five rows of the bag (it scrolls), the badges or the settings, and what was collected at its foot. The Cafe in town (south of the main road, by the duck pond) is the one place to rest: there are no coffee machines. The barista restores energy and moves after a rest jingle of almost three seconds (the cue `rest`; the text waits for it, with reduced motion it does not), played as a scene: four mugs on a tray are poured one after another with the notes of the tune, a sparkle, then the energy bar fills (`restScene` in `engine/engine.ts`), and every defeat, wherever it happens, wakes the player up in front of her (`respawn` in `content/world.ts`). The bot that plays the game in the tests walks back to her when it is at half energy, or before it faces a boss while hurt. The shopkeeper at the counter opens the shop (`engine/shop.ts`): a list with the price and how many are in the bag, up and down to choose, left and right pick how many (shown between arrows on the row under the cursor, whose price is then the total), A buys them, B or LEAVE closes it; it never sells for more coins than the player has, nor more than 9 of one item, and the picker stops there too and says which of the two it is. It sells a stroopwafel, coffee, an energy drink, green tea (restores the PP of every move), a bug spray (no wild enemies for 60 steps in tall grass) and pizza. Coins, like all progress, are in memory only. Nothing in the shop is needed: the balance test is made for a player who buys nothing, and the bot that plays the game in `npm test` closes the shop without spending a coin. What is said in the cafe is `CAFE_TEXT` in `story.ts` (a draft to rewrite). The cafe is 17 cells wide (it scrolls sideways); its right part is the Music Corner (a label in `REGIONS`): a small stage across the top (`:` boards and `^` the front edge, walked on), two pairs of chairs facing it, a flute player, a listener and a regular (`CAFE_TEXT` in `story.ts`, drafts). On the stage stands a player piano (`k` in `CAFE`): A opens its selector, a list of pieces like the shop's (the name; the artist and the length in m:ss of the one under the cursor; a long list scrolls, seven rows at a time; the title row counts where the cursor is of how many, `3/10`, and a small still arrow at the right of the list, the text box's "more" mark, shows where pieces are out of view above or below; the status region says it too, "... 4:57. 1 of 10."), A plays the one under the cursor, B closes it. The list is `PIECES` in `content/pieces.ts`: to add a piece, write its track in `music.ts` (play-once, every voice `pluck`; its level is set by its energy, `levelled` in `music.ts`: the cafe tune's, its loudest step no louder than the loudest tune's) and add one line there (`id`, `name`, `artist`, `track`); the length is computed from the track. The player piano is deliberately outside the four-voice Game Boy rule that every other tune follows: it is an instrument in the world and should sound like a piano, not a chiptune, so its pieces may have up to six voices (two of them triangles; five are used now). The other tunes, the cries and the effects keep the Game Boy's limit, and a test (`audio/score.test.ts`) guards both rules. The first piece: the cafe tune gives way to the first movement of the Moonlight Sonata, the whole Adagio sostenuto, listed as MOONLIGHT SONATA MVT 1 so a player sees it is the first movement only (`moonlight` in `music.ts`: bars 1 to 69, the last chord held under its fermata, 4:57 at 56 quarter notes a minute, checked bar by bar against a Creative Commons BY-SA 2.5 engraving of the sonata (`content/piano.test.ts` holds the notes); a step is a twelfth of a beat, so its `bpm` is 168 and the triplets and the dotted rhythm of the melody are exact; a double sharp is written `##`; five plucked voices (the left hand's octaves and inner chord notes too), `pluck` in `score.ts`), while its keys and roll move and a note floats up (one still picture with reduced motion). The second piece: Scarborough Fair, a traditional English song, in the version from the soundtrack of the anime SukaSuka by Kato Tatsuya, down once in the selector (`scarborough-fair` in `music.ts`, 2:26; `content/scarborough.test.ts` checks it), converted from a MIDI file linked with the YouTube video j6sZX-u9Nbk, reduced to five chiptune voices and quantized (that MIDI changes tempo six times, so its notes are placed on a fixed grid of 75 ms in real time; how is written above the track); the MIDI is not in the repository. The third piece: Always in my heart, from the anime SukaSuka (Shumatsu Nani Shitemasu ka?), composed by Kato Tatsuya, down twice in the selector (`always-in-my-heart` in `music.ts`, 3:46; `content/always.test.ts` checks it). It is converted from a piano arrangement published as a MIDI file with the YouTube video IGW-TD92vi0, whose author allows its use anywhere with credit to the original composer and to the arranger (the arranger of that video); reduced to five chiptune voices and quantized (the MIDI's tempo, 91.9 a minute, on a grid of 32nd notes; how it was converted is written above the track). The MIDI is not in the repository. The fourth piece: Unravel, the Tokyo Ghoul opening, by TK of Ling tosite sigure, down three times in the selector (`unravel` in `music.ts`, 1:27; `content/unravel.test.ts` checks it), converted from the MIDI file of a piano cover by Cosmic PIANO (YouTube video SdIawoVY-eM), reduced to five chiptune voices and quantized with the same rules (its tempo, 134.5 a minute, on a grid of sixteenths); that MIDI is not in the repository either. The fifth piece: aLIEz, the second ending of the anime Aldnoah.Zero, down four times in the selector (`aliez` in `music.ts`, 1:39; `content/aliez.test.ts` checks it), converted from a MIDI file linked with the YouTube video EC7yNPoayh4, reduced to five chiptune voices and quantized with the same rules (its tempo, 99 a minute, on a grid of sixteenths); that MIDI is not in the repository either. The sixth piece: Guren no Yumiya, the opening of the anime Shingeki no Kyojin (Attack on Titan), down five times in the selector (`guren-no-yumiya` in `music.ts`, 1:34; `content/guren.test.ts` checks it), converted from a MIDI file linked from sheet.host (page L775Nx), reduced to five chiptune voices and quantized with the same rules (its main tempo, 92 a minute, on a grid of 32nd notes); that MIDI is not in the repository either. The seventh piece: Ichiban no Takaramono, from the anime Angel Beats!, by ANANT-GARDE EYES & Maeda Jun (as the MIDI's text event names them), down six times in the selector (`ichiban-no-takaramono` in `music.ts`, 2:42; `content/ichiban.test.ts` checks it), converted from a MIDI file linked from sheet.host (page mbqUWS), reduced to five chiptune voices and quantized with the same rules (its tempo, 108 a minute, on a grid of sixteenths); that MIDI is not in the repository either. The eighth piece: Bauklotze, full piano version, down seven times in the selector (the list scrolls; `bauklotze` in `music.ts`, 3:44; `content/bauklotze.test.ts` checks it), converted from a MIDI file linked from sheet.host (page ZBNZH5), reduced to five chiptune voices and quantized (its slowings kept: the notes are placed on a fixed grid of 83.3 ms in real time); that MIDI is not in the repository either. The ninth piece: Clannad Medley, from the anime Clannad, down eight times in the selector (`clannad-medley` in `music.ts`, 13:46, the longest by far; `content/clannad.test.ts` checks it), converted from a MIDI file linked from sheet.host (page E2NJZb), reduced to five chiptune voices and quantized (its tempo and meter changes kept: the notes are placed on a fixed grid of 75 ms in real time); that MIDI is not in the repository either. The tenth piece: My Soul, Your Beats!, from the anime Angel Beats!, down nine times in the selector (`my-soul-your-beats` in `music.ts`, 1:29; `content/my-soul.test.ts` checks it), converted from a piano and vocals MIDI file linked from sheet.host (page zuICKd), its copyright event naming www.youtube.com/ZackyAnimePiano, reduced to five chiptune voices and quantized (its tempo, 145 a minute, on a grid of sixteenths; the vocal is the melody); that MIDI is not in the repository either. To remove a piece, delete its line in `PIECES` and its track in `music.ts` (and its test). The piano stops at the end of a piece, on a second A, when the player leaves the cafe or rests, and the cafe tune starts again; with reduced motion, where no clock runs, the page tells the engine when the piece has had its time (`elapsed`). The roads east and west are routes: the way out crosses bands of tall grass, and the way back hops down ledges and stays out of it. A ledge is a tile with `ledge: <direction>` in the `OUTDOORS` legend (`$` and `}` on the maps): walked onto in that direction it is one move that goes two cells (an arc with a shadow and a sound; one press with reduced motion), from every other side it is a wall; tests prove that the way out needs the grass, the way back does not, and that no cell of a route is a dead end. Hobby Hills is a ring road around a pond with a jetty, a stream with stepping stones, cottages and people; what they say is `HILLS_FOLK` and its one sign, at the entrance, only names the place (drafts to rewrite), and a test keeps every stop within three steps of the ring road or a path. Walking onto a map, or into a named part of one (`REGIONS` in `maps.ts`), slides a label with its name in from the top (`engine/banner.ts`; with reduced motion it appears and disappears). A battle starts with a transition over the map, counted in ticks in the state (`engine/transition.ts`): a blink and closing blinds for a wild enemy, two blinks and a closing iris for a boss (1.8 s), each with its own sound (`encounter`, `showdown`) while the music is silent; a boss that follows another one in the same talk (`quick` on the `battle` action: the second and third battle of the last fight) gets a short one of 0.6 s, one blink and a quick iris with the sound `round`; with reduced motion there is none. The battle screen has a box per fighter in one style (name and level, an energy bar, a bracket), with the numbers and a thin XP bar for the player only. The four badges open the Contact Office, where Wesley is the final boss: three battles in a row (`FINAL_BOSSES` in `battles.ts`, his lines in `FINALE` in `story.ts`, a draft to rewrite), then the contact details and the ending; the rest of the world is optional. The cave has two floors. The ladder down from the first (`CAVE_MAP`) is hidden on purpose, behind a wall: in the east wall of the chest room at the far end the rock has a crack (`w`, drawn almost like the rock around it), and looking at it with A makes it give way for good, together with the two cells of rock behind it (`x`, `y`). No sign points to it; the lost developer in the cave gives a hint (`DEEP_TEXT.hint` in `story.ts`: what to look for, not where). Tests check that no cell behind the wall is within the light of any cell a player can stand on while it is shut, that a search finds the way down, and that nobody gets trapped on either side; the floor below (`DEEP_MAP`, with its rules in the comment above it) holds three puzzles in a row, then THE OUTAGE behind a door for level 5, and the prize. The puzzles: boulders that are pushed onto pressure plates (`engine/push.ts`; a lever, or climbing out and back in, puts them back, and a doorway cell `=` can never be blocked), slick rock that is slid over until something stops the slide (a pale tile with slanting streaks; the status region is told which way a slide went, how far and what stopped it, "You slide down 5 steps and stop against a rock.", and a press that goes nowhere says why; what a tile is called there is its `name` in the `CAVE` legend; one note explains the slide and a second gives the whole floor in words, written by `slickInWords` from the map), and three terminals to use in the right order (`git add`, `commit`, `push`; a wrong one starts it over). A solved puzzle stays solved. Fire bowls light the puzzle rooms in the dark (`light` on a tile), and every push, slide, plate and lever is told to the status region. `content/puzzles.test.ts` proves the puzzles by playing them: a search over the pure engine (`engine/solve.ts`) finds a solution for each one (`PUZZLES` in `story.ts` says where each starts and what solves it) and shows that from every state it can get into, the solution, the reset and the way out are still within reach; the bot and the browser Pilot use the same search, and the browser test plays all three puzzles with motion on (`pilot.motion(true)`). What is said down there is `DEEP_TEXT` in `story.ts` (a draft to rewrite). Signs and people speak in the world, short and without directions or keys (a test, `content/story.test.ts`, keeps the words of a tutorial out and checks that the whole career is still told). Fences join their neighbours: a tile with `join` in a legend is drawn by the sides it shares with more of the same (`fence-ew`, `fence-ns`, corners and ends; `parseMap` picks the piece). The mountain by the West Road is a tile with `relief`: one rock, each cell drawn by the open ground beside it (a face with a lit top, a side edge and a shadow at its foot; bare rock inside; big peaks only on the top ridge; `reliefLook` in `engine/world.ts`), the mouth of the cave standing on mountain (`k`). In battle the fighters breathe with motion (`idleOffset` in `engine/battle.ts`). In colour the things in the water (lily pads, reeds, the duck, the jetty, stepping stones) are drawn over the water of their cell, in their own palettes. In a battle the player is a 32x32 trainer seen from behind (`scripts/sprites/trainer.mjs`); with motion a hit blinks the one hit twice with a spark and then drains its bar (`hitLook` in `engine/battle.ts`), and a new move asks "Replace X with Y?" before an old one is forgotten. Tall grass rustles for 0.4 s where the player walks in and out of it (`trail` in the state); the rubble of the cave, where wild things hide too, does not. The Start menu has a DEX tab (between the badges and the settings): every monster by its number, in the order of `DEX` in `content/dex.ts` (the wild ones by area, then the guardians, then Wesley's three; with a line about each and the region it lives in, or BOSS: drafts to rewrite, with a HOW TO EDIT). A monster is in it once it has been met in a battle (when it is in place and cries); until then its row says ???, and the list counts SEEN n/26. A on one seen opens its page: its battle picture, the text, where it lives, and CRY and BACK (left and right; A presses; B goes back), with up and down to the previous or next one seen. CRY plays its cry, which pauses the tune of the map for as long as it lasts. Like all progress it is kept in memory only, and it unlocks nothing. After the last fight the ending screen shows > KEEP EXPLORING once it has held for a second (with reduced motion: after one press, which it does not take), so an A already on its way does not leave it; A or Start (on a touch screen, a Keep exploring button under the contact lines) puts the player back where they stood, in front of Wesley, with everything kept: the game stays finished, and the world (stars, the hobby stamps, wild monsters, the cafe and its shop, the cave) stays as playable as before (`content/postgame.test.ts`). Talking to Wesley after the end gives `FINALE.again` (a draft) and the contact details, then the ending screen again; the fight is never fought twice. `play` starts a new game only from the ending screen; a game that explores after the end is picked up like any other. Only one label shows at a time at the top of the screen: a note after a find and the name of a place take each other's place. People turn to you when you talk to them: each is drawn by hand from the front, from behind and from the left in `scripts/sprites/characters.mjs`, and `scripts/sprites/generate.mjs` only mirrors the left side for the right. A test proves the first move beats every enemy from full energy at the worst luck, at the lowest level a player can have in each place. `npm test` plays the whole game with a bot and fails if it can no longer be finished
- `scripts/sprites/*`: the game's pixel art as text (`tiles.mjs`, `scenery.mjs`, `characters.mjs`, `enemies.mjs`, `font.mjs`; one character is one pixel, `0`-`3` are the four shades, `.` is see-through). After a change run `npm run sprites`: it rewrites the PNG sheets and `atlas.ts` in `src/features/terminal/game/assets/` (commit them; a test fails when they are out of date). `npm run sprites -- --preview <folder>` also writes 4x enlarged copies to look at. The four shades are `PALETTE` in `generate.mjs`
- `src/assets/*`: images and sounds, imported by components
- `public/*`: served as-is (the `docs/` PDF)

## Deployment

GitHub Actions (`.github/workflows/deploy.yml`) type-checks, lints, tests and builds on every push and pull request, and deploys `dist/` to GitHub Pages from `main`.

**One-time setting:** in the repository settings, Pages, Build and deployment, set Source to **GitHub Actions**. Do this *before* merging the migration: with the old "Deploy from a branch" source the raw `index.html` is served and the page is blank. The custom domain is managed in the repository's Pages settings (Custom domain: `www.wesleyegbertsen.nl`, Enforce HTTPS on), not by a file: an Actions-based Pages deploy ignores `CNAME`. After switching the source, confirm the domain and HTTPS still show in the settings, and after the first deploy check the live site and the PDF URL.

Rollback: revert the merge commit on `main`, or set the Pages source back to the branch deploy.
