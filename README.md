# wesleyegbertsen.github.io

Personal site at <https://www.wesleyegbertsen.nl/>, built with Vite, React and TypeScript.

## Develop

```
npm ci
npm run dev        # dev server
npm test           # unit and component tests
npm run typecheck
npm run lint
npm run build      # production build into dist/
npm run e2e        # real-browser tests with Playwright (see .claude/skills/site-e2e)
```

Node 24 or newer (see `.nvmrc`).

`package.json` has an npm `overrides` entry that lets `eslint-plugin-jsx-a11y` run on ESLint 10: the plugin works there (checked with deliberate violations) but its declared peer range still stops at ESLint 9 (upstream: jsx-eslint/eslint-plugin-jsx-a11y#1075). Remove the override once a release declares support.

TypeScript runs side by side, as Microsoft recommends for 7.0: `tsc` (typecheck and build) is TypeScript 7 (`@typescript/native`), while the package named `typescript` is the 6.0 compatibility package (`@typescript/typescript6`), because TypeScript 7 has no programmatic API and `typescript-eslint` needs one (tracked in typescript-eslint#10940; a new API is expected in TypeScript 7.1). When `typescript-eslint` supports TypeScript 7, point `typescript` back at the real package and drop `@typescript/native`.

## Layout

An architecture overview drawn from the code, with source citations, is in [docs/architecture/overview.html](docs/architecture/overview.html) (open it in a browser).

- `src/features/*`: the hobby easter eggs (matrix backdrop, Poké Balls, cat, Game Boy), each with its hooks and tests
- `src/pages/*`: the two routed pages, `HomePage` (`#/`) and `ProjectsPage` (`#/projects`); `src/App.tsx` holds what every page shares (backdrop, site menu, Game Boy, social bar)
- `src/components/*`: the social bar and its panels, the left site menu (`SiteMenu`) and the project card
- `src/data/*`: skills, work experience, education, menu items and projects as typed data, edit these to update the site: add a line to `navigation.ts` for a menu item, add an entry to `projects.ts` (with screenshots in `src/assets/images/projects/`) for a project
- `src/features/theme/*`: the matrix background colour is the site theme. `themes.ts` holds one palette per colour (green, red, blue, white) and is the only place to change a colour; a test checks every pairing for contrast. The chosen theme is set on `<html>` as `data-theme` plus the CSS custom properties `--accent`, `--accent-hover`, `--accent-on-light`, `--accent-soft` and `--on-accent`, which the CSS modules use instead of hard-coded colours (GitHub and LinkedIn keep their brand colours)
- `src/features/terminal/*`: the shell on `#/terminal`. Its `play` command opens Career Quest, a Game Boy-style adventure in `game/`: `engine/` is the pure game logic, `content/` is what to edit (maps as text grids in `maps.ts`: the town, the routes east and west, Hobby Hills and the cave; people, signposts, gold stars, errands and the ten hobby stops (`HOBBIES`, a draft to rewrite) in `story.ts`; enemies per area (`AREAS`), levels and XP (`LEVELS`), the moves offered at level 5 and 10 (`LEARN`), items, the money (`ECONOMY`) and what the shop sells (`SHOPS`) in `battles.ts`; the tunes and sound effects as note text in `music.ts` (a way between maps says which effect it is: `door`, `path` or `cave`); the facts come from `src/data`), `render.ts` draws it on a 160x144 canvas, `audio/` plays the music and the effects (synthesized with the Web Audio API like a Game Boy: two pulse voices, a triangle and noise; no audio files). `M` or the Sound button switches the sound off; the Start menu has a Settings tab with the sound switch, the volume (left and right, 0 to 100%, 50% at the start; 100% is master gain 0.25) and the LCD look of the screen (a CSS grid laid over the canvas, on by default); all three are kept in memory for the session (`settingsStore.ts`). Wins give XP (levels 1 to 10) and COINS: the enemy's level times 2 for a wild one, times 10 for a boss; the Start menu shows them. The Cafe in town (south of the main road, by the duck pond) is the place to rest: the barista restores energy and moves, and a defeat in town wakes the player up in front of her (`respawn` on the town map; elsewhere a defeat goes back to the last coffee machine or barista used). The town has no coffee machine of its own any more; the ones inside the buildings, on the two routes, in Hobby Hills and in the cave stay. The shopkeeper at the counter opens the shop (`engine/shop.ts`): a list with the price and how many are in the bag, up and down to choose, A buys one, B or LEAVE closes it; it never sells for more coins than the player has, nor more than 9 of one item. It sells a stroopwafel, coffee, an energy drink, green tea (restores the PP of every move), a bug spray (no wild enemies for 60 steps in tall grass) and pizza. Coins, like all progress, are in memory only. Nothing in the shop is needed: the balance test is made for a player who buys nothing, and the bot that plays the game in `npm test` closes the shop without spending a coin. What is said in the cafe is `CAFE_TEXT` in `story.ts` (a draft to rewrite). The roads east and west are routes: the way out crosses bands of tall grass, and the way back hops down ledges and stays out of it. A ledge is a tile with `ledge: <direction>` in the `OUTDOORS` legend (`$` and `}` on the maps): walked onto in that direction it is one move that goes two cells (an arc with a shadow and a sound; one press with reduced motion), from every other side it is a wall; tests prove that the way out needs the grass, the way back does not, and that no cell of a route is a dead end. Hobby Hills is a ring road around a pond with a jetty, a stream with stepping stones, cottages and people; what they say is `HILLS_FOLK` and what the signposts call the stops is `STOP_NAMES` in `story.ts` (drafts to rewrite), and a test keeps every stop within three steps of the ring road or a path. Walking onto a map, or into a named part of one (`REGIONS` in `maps.ts`), slides a label with its name in from the top (`engine/banner.ts`; with reduced motion it appears and disappears). A battle starts with a transition over the map, counted in ticks in the state (`engine/transition.ts`): a blink and closing blinds for a wild enemy, two blinks and a closing iris for a boss, each with its own sound (`encounter`, `showdown`) while the music is silent; with reduced motion there is none. The battle screen has a box per fighter in one style (name and level, an energy bar, a bracket), with the numbers and a thin XP bar for the player only. The four badges open the Contact Office, where Wesley is the final boss: three battles in a row (`FINAL_BOSSES` in `battles.ts`, his lines in `FINALE` in `story.ts`, a draft to rewrite), then the contact details and the ending; the rest of the world is optional. People turn to you when you talk to them: their back and side pictures are derived from the one front drawing by `scripts/sprites/generate.mjs`. A test proves the first move beats every enemy from full energy at the worst luck, at the lowest level a player can have in each place. `npm test` plays the whole game with a bot and fails if it can no longer be finished
- `scripts/sprites/*`: the game's pixel art as text (`tiles.mjs`, `scenery.mjs`, `characters.mjs`, `enemies.mjs`, `font.mjs`; one character is one pixel, `0`-`3` are the four shades, `.` is see-through). After a change run `npm run sprites`: it rewrites the PNG sheets and `atlas.ts` in `src/features/terminal/game/assets/` (commit them; a test fails when they are out of date). `npm run sprites -- --preview <folder>` also writes 4x enlarged copies to look at. The four shades are `PALETTE` in `generate.mjs`
- `src/assets/*`: images and sounds, imported by components
- `public/*`: served as-is (the `docs/` PDF)

## Deployment

GitHub Actions (`.github/workflows/deploy.yml`) type-checks, lints, tests and builds on every push and pull request, and deploys `dist/` to GitHub Pages from `main`.

**One-time setting:** in the repository settings, Pages, Build and deployment, set Source to **GitHub Actions**. Do this *before* merging the migration: with the old "Deploy from a branch" source the raw `index.html` is served and the page is blank. The custom domain is managed in the repository's Pages settings (Custom domain: `www.wesleyegbertsen.nl`, Enforce HTTPS on), not by a file: an Actions-based Pages deploy ignores `CNAME`. After switching the source, confirm the domain and HTTPS still show in the settings, and after the first deploy check the live site and the PDF URL.

Rollback: revert the merge commit on `main`, or set the Pages source back to the branch deploy.
